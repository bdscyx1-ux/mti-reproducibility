Algorithm S1. Full-Recompute Flow Field (C-FF)

DESIGN_OR_DEFINITION_TRANSCRIPTION | Source manuscript: design/definition prose

Algorithm S1. Full-Recompute Flow Field (C-FF)
Input: grid G, canonical goal set T, legal-move relation N(.) Output: integration J, owner O, and next-cell direction D 1 Allocate fresh arrays; set J[v] <- INF, O[v] <- NIL, and D[v] <- NIL for every v in V 2 Q <- empty deterministic min-heap 3 for each walkable goal t in T, in canonical order do 4 J[t] <- 0; O[t] <- t; push the current record for t into Q 5 while Q is not empty do 6 u <- pop a record from Q; if stale, continue 7 for each legal predecessor p of u do 8 candidate <- c(p, u) + J[u] 9 if (candidate, O[u]) improves (J[p], O[p]) then 10 J[p] <- min(J[p], candidate); O[p] <- O[u]; push the revised p into Q 11 for each walkable, reachable, non-goal cell v do 12 S <- {s in N(v) : c(v, s) + J[s] equals J[v]} 13 D[v] <- deterministic minimum of S by (total, owner, remainder, coordinate) 14 assert O[v] equals O[D[v]] 15 return (J, O, D) On every accepted grid change, build a fresh field by lines 1-15, then replace the old field. A plan query follows D until the declared owner goal and requires J to decrease at each step.

Algorithm S2. Incremental Dynamic Flow Field (IDFF)

DESIGN_OR_DEFINITION_TRANSCRIPTION | Source manuscript: design/definition prose

Algorithm S2. Incremental Dynamic Flow Field (IDFF)
Input: updated grid G; change set C; persistent field, Q, revisions, dirty set, cursor Output: a queryable field or a resumable PENDING state 1 For a new change set, mark repair pending and make the field non-queryable 2 A <- changed cells and their clipped 3 x 3 dependency neighborhoods 3 for each v in A, mark its direction dirty; UPDATE-VERTEX(v) 4 while the queue phase is unfinished do 5 if the budget expired then preserve state and return PENDING 6 u <- pop the next non-stale inconsistent vertex, if any 7 if none remains then sort dirty cells, set cursor to 0, and end this phase 8 else if (rhs[u], rhsOwner[u]) precedes (g[u], gOwner[u]) then 9 (g[u], gOwner[u]) <- (rhs[u], rhsOwner[u]); invalidate u's queue revision 10 else (g[u], gOwner[u]) <- (INF, NIL); UPDATE-VERTEX(u) 11 if u was processed, UPDATE-VERTEX each predecessor 12 if u was processed, mark its changed direction dependencies dirty 13 while dirty cells remain from the saved cursor do 14 if the budget expired then preserve state and return PENDING 15 v <- next dirty cell; advance cursor; clear D[v] 16 if v is walkable, reachable, and not a goal then 17 D[v] <- deterministic successor s with c(v, s) + g[s] equal to g[v] 18 clear pending and dirty state; expose the field; return COMPLETE UPDATE-VERTEX(v): 19 if v is a walkable goal then (rhs[v], rhsOwner[v]) <- (0, v) 20 else use the best legal successor via g; blocked/no successor gives (INF, NIL) 21 increment v's revision, invalidating its older queue entries 22 if g and rhs cost/owner pairs differ, enqueue v with the revised key A resume skips lines 1-3 and retains its queue phase and direction cursor. A plan call resumes pending repair before following the consistent direction field.

Algorithm S3. Managed multi-query execution with private lane state

DESIGN_OR_DEFINITION_TRANSCRIPTION | Source manuscript: design/definition prose

Algorithm S3. Managed multi-query execution with private lane state
Input: algorithm A in {C-FF, IDFF}, 16 frozen lane inputs B, worker count W, CPU plan P Output: complete-batch time T and validated results R[0..15], or batch failure 1 Load and verify B and cached oracle outcomes before batch timing 2 Create W fixed workers; worker j binds to P[j], signals READY, and waits 3 Coordinator waits for every READY signal; start clock; release workers 4 In parallel, each worker j executes lanes i = j, j + W, ... < 16: 5 if batch failure is already flagged: skip each unstarted lane 6 otherwise verify the worker CPU binding and enter the lane 7 Deserialize private B[i]; build private grid G; create planner A 8 try: 9 Initialize A; require valid status, budget, and grid version 10 Run all initial queries; validate paths and record outcomes 11 for each of the 24 event groups in frozen order: 12 for each atomic partition in its prescribed order: 13 Require no pending repair; apply the changes to G 14 Call A.ApplyChanges using the technical budget 15 Require completed repair, valid budget, matching versions 16 Run all fixed-start queries; validate paths; record outcomes 17 Require the full query and repair counts; store result R[i] 18 finally: reset the lane planner 19 On a lane error: flag batch failure; stop admitting unstarted lanes 20 Fingerprint successful results; verify the ending CPU binding 21 On a binding error: flag batch failure 22 Each worker clears its binding and signals DONE after its lane loop 23 Coordinator waits for all DONE signals; stop clock at T; join workers 24 Require 16 completed lanes, no failed/skipped lanes, and valid bindings 25 Compare every recorded query with its cached oracle after timing 26 If any check fails: reject the complete batch; do not retry or replace 27 Return T and results in ascending lane order Within a lane, C-FF and IDFF execute the serial procedures of Algorithms S1 and S2.
