# Gate 13R-PR2 formal execution prelaunch test design v1

The prelaunch suite must pass before the formal execution receipt or formal root can exist.

1. Verify every user-specified active v2 artifact by exact SHA-256 and parse its schema/identity.
2. Reconstruct all 3,552 process records and 10,176 sample identities, all 74 campaigns, 1,008 matched superblocks, AB/BA 24/24 per heterogeneous scenario, and order-by-row 12 per cell.
3. Verify Windows PowerShell 5.1 and active-runtime parsers, parameter binding, explicit absolute `ProjectPath`, native Windows PowerShell 5.1 `PSModulePath`, and output-root isolation.
4. Prove the Unity formal adapter is mechanically derived from the frozen PR1B v3 command and changes only formal authorization/bindings, 2-or-4-sample cohort acceptance, and formal evidence identities.
5. Exercise synthetic two-sample and four-sample Williams plans, duplicate IDs, wrong rows, path escape, missing receipt, wrong receipt hash, non-formal plan, and injected-failure rejection without producing formal samples.
6. Compile the project and run the adapter memory-policy, path-safe atomic, and PSAPI/CIM telemetry probes in verification-only roots.
7. Verify zero unrelated Unity processes, Unity lock hygiene, entitlement/license, network, power scheme, no-sleep policy, AC state, environment/thermal snapshot, free physical memory, and at least 57,397,541,440 original free bytes on H:.
8. Prove all frozen upstream roots/key files are byte-identical before and after prelaunch validation.
9. Require the formal root and formal execution receipt to remain absent throughout prelaunch validation.
10. Test the raw/analysis two-phase state machine: ordinary post-collection auditor or analysis failures cannot select a Unity retry path; only a proven raw-contract violation can block raw-data commit, and even that requires separate user authorization for any new experiment.
11. Test deterministic, non-self-referential raw payload hashing, per-file manifests, end-environment snapshot, atomic freeze receipt, read-only payload marking, and `RAW-DATA-COMPLETE / ANALYSIS-PENDING / IMMUTABLE` terminal tokens.
12. Test that every future analysis attempt must use an isolated attempt directory, holds the raw root read-only, and verifies the raw payload tree hash before and after analysis.
