# Gate 14Re 四算法单位运动与数量效应实验计划 v1

状态：`DESIGN-STARTED / B16-FROZEN / NON-EXECUTING`

日期：2026-10-15（Asia/Shanghai）

## 1. 研究目的

Gate 14Re 是一项从零建立的独立确认性研究，只回答两个问题：

1. 在预先登记的真实应用输入条件下，四种固定算法中哪一种整体表现更优？
2. 当单位数量增加时，各算法的运动表现和全量渲染性能如何变化？

此前研究路线的原始数据、pilot、分析、样本量计算、实现、收据和结论均不作为 Gate 14Re 的输入、证据或先验。Gate 14Re 不继承任何历史 observation。

## 2. 核心原则

- 每次运行只有一个所有单位共享的终点；同一完整 block 内，四算法使用完全相同的场景、起点、共同终点、单位数量和事件序列。
- 每个算法开始前必须恢复同一冻结初始快照，并清空算法私有状态、预算 telemetry 和上一算法产生的运行状态；四算法之间唯一允许不同的是算法身份及 Williams 顺序位置。
- 四算法本身、移动语义、碰撞语义和预算语义保持生产实现，不为实验制造优势或持续运动假象。
- `B = 16` 是每个正式设计单元的固定独立 block 数；单位、帧、tick 和同一进程内的四个算法结果都不是额外的独立样本。
- 算法顺序采用四行 Williams 平衡顺序；16 个 blocks 中每行恰好出现 4 次。
- 不通过增加 pilot、nuisance-only 分析、Monte Carlo 或重复全树审计来改变 B。
- Gate 14Re 允许得出“没有唯一优胜者”；不得为了必须选出一个算法而改变规则。

## 3. 实验对象和条件

### 3.1 算法

正式执行前绑定四个生产算法实现及其程序集 SHA-256，记为 `A`、`B`、`C`、`D`。盲化标签只用于分析阶段；最终报告恢复真实算法名称。

### 3.2 应用条件

- 主比较模块使用 8 个预先登记的应用条件 `C01`–`C08`。
- 数量效应模块从这 8 个条件中预先指定 2 个代表性 anchor 条件 `Q1`、`Q2`。
- 条件、输入实例和共同终点必须在任何正式结果产生前冻结；运行失败后不得按结果重新抽取条件或终点。
- 每个输入实例必须可达、起点有效、共同终点有效，并能由独立参考路径检查器确认。

### 3.3 单位数量

数量水平固定为：

`N = {1, 8, 32, 128, 512}`

主比较使用其中一个预先指定的 `N_primary`。数量效应模块复用主比较中两个 anchor 条件在 `N_primary` 上的数据，并只补采另外 4 个 N 水平。

`AUTHOR_INPUT_NEEDED: 在正式实现冻结前指定 N_primary；它必须属于上述五个水平。`

## 4. 两条测量 lane

### 4.1 Movement lane

使用真实导航、真实单位状态和共同终点，记录：

- **M1 完成时间**：从测量起点到全部登记单位满足预先冻结的共同终点到达规则；越低越好。算法超时或有单位未完成是结果，不得删除。
- **M2 轨迹代价**：在共同有效 mask 上计算的实际轨迹代价或相对参考路径代价；越低越好。
- **M3 可靠性**：完成、超时、无路径、预算耗尽和其他预先登记终态。
- **M5 正确性/安全性**：预先登记的碰撞、非法位置、越界或其他正确性违规事件。

### 4.2 Full-population M4 lane

- 场景中实际生成并渲染全部 N 个单位，使用与 Movement lane 相同的真实导航语义。
- 记录测量窗口内逐帧 frame time；M4 以 frame time 为原始量，报告中同时给出便于理解的派生 FPS。
- 主要摘要为 median frame time 和 P95 frame time；数量曲线按算法和 N 展示。
- 已完成或停止的单位保持真实系统行为；不得强制移动、复活或循环目标。

## 5. 固定样本量与运行规模

### 5.1 Williams 顺序

四行固定为：

1. `A-B-D-C`
2. `B-C-A-D`
3. `C-D-B-A`
4. `D-A-C-B`

在每个设计单元的 16 个 blocks 中，每行使用 4 次。每个 block 在一个 fresh Unity process 中依次执行四算法。

### 5.2 主比较模块 A

`8 conditions × 1 N_primary × 2 lanes × B16 = 256 fresh processes`

每个进程产生四个算法的 lane-specific sample，因此为：

`256 × 4 = 1,024 algorithm samples`

### 5.3 数量效应模块 Q

两个 anchor 条件在 `N_primary` 上的数据由模块 A 提供；只补采其余四个 N 水平：

`2 anchors × 4 additional N levels × 2 lanes × B16 = 256 fresh processes`

即：

`256 × 4 = 1,024 algorithm samples`

### 5.4 总规模

- 计划有效 blocks / fresh processes：`512`
- 四算法 lane-specific samples：`2,048`
- 每个正式设计单元的独立样本量：`B = 16`

基础设施故障可整 block 替换一次，但替换不增加可分析样本量；算法特异的失败、超时或不完成属于结果，不替换。

## 6. 选优规则

### 6.1 资格门槛

先按预先冻结的 M3、M4、M5 工程门槛判断算法是否具备应用资格。未满足门槛的算法不能因 M1 更快而成为最终推荐。

`AUTHOR_INPUT_NEEDED: 在正式执行前冻结 M3、M4、M5 的工程阈值或事件判定表。`

### 6.2 主判据与护栏

1. **M1 为主判据**：在全部 8 个条件、固定 `N_primary` 上比较完成时间。
2. **M2 为护栏**：M1 候选算法不得出现超过预先容许幅度的轨迹代价恶化。
3. **M2 为次级比较**：若 M1 无法唯一确定优胜者，且候选均满足 M2 护栏，则使用 M2 作次级工程比较。
4. **不强制赢家**：仍无法唯一判定时，报告并列候选集和造成不确定性的条件。

`AUTHOR_INPUT_NEEDED: 冻结 M1 的最小实际重要差异 δ_M1，以及 M2 的最大容许恶化 δ_M2。`

### 6.3 确认性统计

- 以完整 input block 为独立单位，四算法结果按 block 配对。
- M1 对正值采用 log 变换并报告算法比率及 95% 置信区间；算法总体比较后，对 6 个成对比较使用 Holm 校正。
- M2 使用共同有效 mask，不因算法结果改变 mask；报告配对差异或比率及 95% 置信区间，并按同一成对比较族控制多重性。
- M3、M5 报告 block-level 事件比例及不确定性；不能把帧或单位当作独立 n。
- M4 以 block-level median/P95 frame time 为分析输入，展示 frame time 和派生 FPS，但不把 3,600 个帧当作 3,600 个独立样本。
- 只有当一个合格算法对所有其他合格算法都满足预先冻结的 M1 优胜规则，并通过 M2 护栏时，才称为唯一优胜者。

## 7. 数量效应分析

- 对两个 anchor 条件分别绘制 `N={1,8,32,128,512}` 下的 M1 和 M4 曲线。
- 确认性模型使用 `log2(N)`、算法及其交互项；完整 block 仍是独立单位。
- 算法×数量交互回答“某算法是否随 N 增长得更快或更慢”，不能由某个 N 的单独显著性替代。
- M2、M3、M5 随 N 的变化作为支持性结果，并明确标注其角色。
- 最终选优仍以 `N_primary` 的主比较为准；数量曲线用于判断推荐算法的适用范围和扩展性。

## 8. 最小必要准备

Gate 14Re 在正式运行前只保留以下四步：

1. **一次设计冻结**：确定 8 个条件、2 个 anchors、`N_primary`、工程门槛、`δ_M1` 和 `δ_M2`。
2. **一次实现与编译验证**：实现 runner、两条 lane、block 日志和输出 schema，并通过 compile-only 与纯 synthetic known-answer checks。
3. **一次短现场预检**：验证共同终点、四算法顺序、完整 N 渲染、输出完整性，并在 `N=512` 做代表性资源准入。
4. **一次正式 Phase A**：只有用户另行明确授权后，才创建正式 measured root 并运行 512 个计划 blocks。

明确不设置：数值 pilot、盲化 nuisance projection、Monte Carlo 样本量搜索、历史 raw tree 重扫、为每个小修复重跑全部旧门禁。

## 9. 故障和排除规则

- 进程崩溃、磁盘写入失败、错误场景或错误绑定属于基础设施失败；整 block 作废，最多重新执行一次，并保留原故障记录。
- 单一算法无路径、预算耗尽、超时、未完成或正确性违规属于算法结果；不得重跑该算法来替换结果。
- 仅因基础设施故障而未能执行完四算法的不完整 block 不进入主估计；算法正常执行后产生的无路径、预算耗尽、超时或未完成仍是有效结果，不能据此把该 block 排除。不得只保留其中表现较好的算法样本。
- 任何事后改变条件、阈值、算法实现、N、指标或选优规则，均产生新的 Gate 14Re 版本，而不是静默修改 v1。

## 10. 数据与报告

- 正式原始数据只进入一个 Gate 14Re measured root；正式分析只进入一个 Gate 14Re analysis root。
- 运行结束后做一次结构完整性检查、逐文件 SHA-256 清单和只读冻结。
- 最终报告至少包含：全部算法的效应量与区间、M1 主比较、M2 护栏、M3/M5 资格结果、M4 数量曲线、算法×数量交互、失败/超时，以及是否存在唯一优胜者。
- 不以 pilot 或历史结果补足缺失正式数据；不隐藏不利条件或无唯一赢家结论。
